## 2. Where the saving came from, and where it did not

The source carries a districts layer (726 geometries) and a states layer (36)
over **one shared arc set**. Extracting the states layer and keeping only the
arcs it actually references drops **1,571 of 2,285 arcs**. That is the entire
saving.

The brief asks for aggressive simplification. I ran the sweep and then did not
apply any, which needs explaining rather than glossing:

```
  minArea    points     bytes   gate
       0      3873     45390   15/15
    0.25      3872     45384   15/15
     0.5      3872     45384   15/15
       1      3872     45384   15/15
       2      3868     45358   15/15
       4      3865     45337   15/15
       8      3856     45275   15/15
      16      3851     45243   15/15
```

Every level from 0.25 to 16 buys **147 bytes in total, 0.3%**. The source is
already generalised to an appropriate resolution for a national choropleth, so
there is no redundant detail left to remove — simplification would go straight
to spending real fidelity (coastline, the Rann of Kutch, the north-eastern river
boundaries) on a third of a percent of a 45 KB file. That is a bad trade made
for its own sake, so `CHOSEN = 0`.

The sweep stays in the script, because it is the evidence for that decision and
because if the source is ever swapped for a higher-resolution one, it will
immediately show both whether simplification is warranted and the level at which
it starts to break the compliance gate.

**One genuine technical point worth recording.** Simplification is done per-arc,
not per-polygon, and that is why TopoJSON matters here rather than GeoJSON. A
shared border is one arc referenced by both neighbours, so simplifying it moves
both sides identically and the seam survives. Simplifying GeoJSON polygons
independently would tear visible gaps between neighbouring states.

## 3. The gate is re-run on the final geometry

This is the part that mattered most. A simplification that shaved a corner off
Aksai Chin would still look like India and would still be unpublishable, so the
check has to happen **after** the geometry is final, not on the raw download.

All 15 probes pass on the built file:

```

PASS  Skardu (Gilgit-Baltistan)   inside, owned by LA
PASS  Muzaffarabad (PoK)          inside, owned by JK
PASS  Mirpur (PoK)                inside, owned by JK
PASS  Aksai Chin interior         inside, owned by LA
PASS  Aksai Chin east             inside, owned by LA
PASS  Shaksgam Valley             inside, owned by LA
PASS  Srinagar / Leh              inside
PASS  Tawang / Itanagar / Walong  inside, Arunachal complete
PASS  Kathmandu / Lhasa / Lahore  outside  (controls)
```

`docs/boundary-check.svg` is the visual proof, regenerated by the same script.

### The gate is now a test, not a script

Section 2.1 is a legal requirement, not a preference, so it should not depend on
anyone remembering to run a script. **Section 15 of the test suite** decodes the
built topology independently of the build script — it does not import it — and
asserts:

- all fifteen probes, including that Aksai Chin, Shaksgam and Gilgit-Baltistan
  are owned by **Ladakh specifically** and PoK by **Jammu & Kashmir**, not merely
  that they fall somewhere inside India;
- the geometry joins one-to-one to `units.json`, with no orphan on either side;
- every polygon ring is closed;
- the file is inside the 400 KB budget;
- the embedded cartographic note names its source *and* its provenance caveat.

If a future change ever moves Aksai Chin outside Ladakh, `node test/run.js`
fails.

## 4. Decisions taken

**Coordinates stay as longitude and latitude.** The brief's repository layout
calls the script a "simplification and projection pipeline", but baking a
projection into the data file would make the projection irreversible. d3
projects at runtime at negligible cost, so this stays a design decision for
Phase 5 rather than a data decision now.

**The join key is our own unit code.** Geometry properties are `{ code, name }`
with `code` already mapped from the Census 2011 state code, so `map.js` joins on
`code` and never on a name string. The Census codes themselves are the reason
this was safe: `26` is the merged Dadra & Nagar Haveli and Daman & Diu, and
`36`/`37`/`38` are Telangana, residual Andhra Pradesh and Ladakh, so the source
was already on the present-day map.

**The cartographic note is embedded in the data file**, under `source`, carrying
the repository, the retrieval date, what the depiction shows, and the provenance
caveat — that the upstream repository declares no licence and makes no Survey of
India claim, so compliance rests on our own geometry test rather than on an
upstream assertion. The page must print this; the test asserts it exists.
